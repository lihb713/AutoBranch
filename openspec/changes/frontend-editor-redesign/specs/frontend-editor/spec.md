## Purpose

行为树可视化编辑器：以真实画布节点呈现行为树（节点对象池 + 槽位引用、主树/游离区自动布局、ref 参数编辑与展开/收缩、即时校验），并支持文档导入导出，是用户构建行为树文档的前端界面。

## ADDED Requirements

### Requirement: 节点画布呈现

系统 SHALL 以真实画布节点呈现行为树：每个节点为固定尺寸卡片，类型用颜色/形状/图标区分，节点显示用户自定义的 `name`。树从根节点在上、向下生长，兄弟节点水平排布；父子关系以连线绘制。节点位置由系统自适应布局，不要求用户手动摆放。

#### Scenario: 呈现一棵行为树
- **WHEN** 用户打开一份行为树文档
- **THEN** 画布按树结构自动布局：根节点在顶、子节点向下生长、同层兄弟水平对齐，父-子以连线相连，每个节点显示其类型图标与 name

#### Scenario: 大树可滚动与缩放
- **WHEN** 行为树宽度/高度超出视口
- **THEN** 画布支持平移与缩放查看整棵树

#### Scenario: 空文档呈现
- **WHEN** 用户打开一份无任何节点（或仅有根节点）的行为树文档
- **THEN** 画布显示根节点占位（无游离树时游离区不渲染），不报错

### Requirement: 节点对象池与槽位引用（统一槽位模型）

系统 SHALL 以"节点对象池 + 槽位引用"建模行为树：全部节点独立定义，节点间一切动作关联经**语义命名槽位字段**（下拉选择）引用子树根节点 id 建立。槽位字段按类型：`Root.body`（1 槽）、`Sequence.actions`（可变槽可增删）、`Step.action`（1 槽）、`IfThenElse.then/else`（2 槽）、`Branch.action`（前置操作槽）+ `branches[].action`（每分支 1 槽）、`Retry.body`（1 槽）、`LoopUntil.action`（1 槽）；叶子 `Action`（`description` 字段）与 `ref` 无槽位。条件（`Step.expect`/`IfThenElse.if`/`Branch.branches[].when`/`LoopUntil.until`）为节点自有字段，不通过槽位。

#### Scenario: 槽位选择子节点
- **WHEN** 用户编辑某容器节点的槽位下拉
- **THEN** 下拉只展示各棵游离树的根（游离树最上层节点；单节点游离树展示其自身），选中后该棵游离树整体挂到该槽位并从游离区移除；已挂载节点与树内非根节点不展示

#### Scenario: 增加/删除槽位
- **WHEN** 用户在 Sequence 点「增加槽位」/删除某槽位
- **THEN** `actions` 数量变化；删除槽位时该槽位原指向的子树回游离区独立成树

#### Scenario: 创建 Step 自动附带 Action
- **WHEN** 用户创建 Step 节点
- **THEN** 系统自动创建一个 Action 子节点挂入其 `action` 槽位（操作部分走槽位）

#### Scenario: 叶子 Action
- **WHEN** 用户查看 Action 节点
- **THEN** 其为画布叶子卡片（`description` 字段编辑），无槽位挂载点

### Requirement: 主树区与游离区

系统 SHALL 将画布分为主树区与游离区：主树区呈现从根节点（`type: Root`）沿槽位引用递归可达的树；游离区呈现**与本文档 Root 不联通的树**。游离树**不含 `type: Root` 节点**，其最上层祖先节点即游离树的"根"（单节点游离树，节点自身即根）。每棵游离树独立布局，顶部带根节点 name + 「游离」标记。游离树允许保存（支持中途保存退出/草稿）。

#### Scenario: 游离树独立呈现
- **WHEN** 画布存在未被根可达的节点/树
- **THEN** 它们在游离区独立布局，顶部显示游离树根节点 name 与「游离」标记；游离树根即其最上层未被任何槽位引用的节点（单节点时节点自身即根）

#### Scenario: 挂载/剥离迁移
- **WHEN** 游离根（某棵游离树的最上层节点）被某槽位选中，或主树某子树被剥离
- **THEN** 前者将该棵游离树整体并入主树布局，后者回游离区独立成树（原子树最上层祖先成为新游离树的根）

### Requirement: 根节点

每份行为树文档 SHALL 有且仅有一个根节点（`type: Root`，真实节点类型，固定 1 槽位，子限制 1）。根节点不可删除/替换；文档执行即执行根节点的子节点。顶层 `root: <id>` 引用指向根节点。

#### Scenario: 文档恰有一个根
- **WHEN** 创建行为树文档
- **THEN** 文档含且仅含一个 `type: Root` 节点，`root` 顶层键引用它

#### Scenario: 根不可删改
- **WHEN** 用户尝试删除或替换根节点
- **THEN** 系统拒绝该操作

### Requirement: 引用节点参数编辑

系统 SHALL 支持编辑引用（ref）节点：用户从下拉选择目标文档，选择后系统自动加载该文档的 `inputs`/`outputs` 声明并生成参数映射表单。入参（args）为列表按序对应被引文档 `inputs`；出参（returns）为字典（键 = 本树新建参数名，值 = 类型）按序对应被引文档 `outputs`。

#### Scenario: 选择引用目标并加载参数
- **WHEN** 用户在 ref 节点下拉选择目标文档
- **THEN** 系统加载该文档 inputs/outputs，展示每个入参的填写框与出参的接收参数名+类型填写框

#### Scenario: 编辑入参
- **WHEN** 用户为每个入参填写传入值
- **THEN** 参数以列表形式按序保存，对应被引文档 inputs；每个值**优先匹配本树已有变量名**（命中即变量引用），未命中则作为字面量（str/int/float/bool）传入

#### Scenario: 编辑出参
- **WHEN** 用户为每个出参填写"本树新建参数名"+类型
- **THEN** 参数以字典形式保存，本树创建对应接收变量

#### Scenario: 跨文档引用环即时拦截
- **WHEN** 用户为 ref 节点选择目标文档，且该文档（直接或间接）引用了当前文档形成循环
- **THEN** 系统即时拒绝该选择并提示循环引用（编辑时检测，越早越好）

### Requirement: 引用展开与收缩

系统 SHALL 支持引用节点展开/收缩：收缩态为单节点占位卡片（显示目标文档名）；展开态显示被引用文档的完整子树（只读预览，不可编辑）。展开逐层懒加载（被引文档内的 ref 默认仍收缩，点击再展开）；收缩某节点时其内已展开的子引用一并收缩。修改被引用文档须进入该文档编辑。

#### Scenario: 展开引用
- **WHEN** 用户点击引用节点展开
- **THEN** 显示被引用文档的根与整棵子树（只读预览），其内引用仍为收缩态

#### Scenario: 收缩引用
- **WHEN** 用户收缩引用节点
- **THEN** 其子树（含已展开的子引用）一并收缩，回到单节点占位

#### Scenario: 被引文档变更后的预览
- **WHEN** 展开预览加载后被引文档被修改/删除
- **THEN** 预览保持已加载的快照，并提示"被引文档已变更，可重新加载"；保存时按最新目标文档校验

### Requirement: 删除与修改语义

系统 SHALL 提供明确的删除/修改语义：删除槽位 = 解引用（子节点回游离区）；删除单节点 = 该节点各槽位子节点各自成为独立游离树；删除子树 = 连带删除全部后代。修改槽位选另一节点 = 旧节点回游离区、新节点入主树。删除 ref 节点仅解除引用，被引用文档不受影响。

#### Scenario: 删除单节点
- **WHEN** 用户删除主树中的中间节点（不选子树）
- **THEN** 该节点消失，其槽位子节点各自成为独立游离树进游离区

#### Scenario: 删除子树
- **WHEN** 用户选择删除某节点及其整棵子树
- **THEN** 该节点与全部后代一并删除，无残留

#### Scenario: 删除当前选中节点后面板清理
- **WHEN** 用户删除当前正在属性面板编辑的节点
- **THEN** 属性面板清空或回退到根节点，不残留已删节点状态

### Requirement: 即时校验与错误提示

系统 SHALL 在编辑时即时校验：节点必填字段未填 → 红框标记 + 错误信息；ref 选目标文档后立即校验 args/returns 对齐（数量/顺序/本树变量存在/接收名不重名/类型匹配）。保存时汇总校验：单根、主树与各游离树无环、ref 目标文档存在、节点配置齐全。错误越早提示越好。

#### Scenario: 必填字段即时标记
- **WHEN** 用户在节点中留空必填字段（如 Step 的 action/expect）
- **THEN** 该字段即时红框标记并显示错误信息

#### Scenario: ref 参数对齐即时校验
- **WHEN** 用户编辑 ref 的 args/returns
- **THEN** 系统即时校验数量/顺序/变量存在/命名冲突/类型匹配并提示

#### Scenario: 保存汇总校验
- **WHEN** 用户保存文档
- **THEN** 系统校验单根、逐树无环、ref 目标存在、节点配置齐全，汇总展示错误清单

### Requirement: 节点标识与命名

系统 SHALL 为每个节点提供 `id`（文档内唯一，自动生成、导入时保留）与 `name`（用户自定义的纯字符串，画布显示名；类型不并入 name，用图标/颜色区分）。`id` 仅含 `[A-Za-z0-9_-]`、长度 ≤64；`name` 长度 ≤64，不强制唯一（以 id 兜底区分）；空 name 画布显示类型名兜底。

#### Scenario: 自动生成 id
- **WHEN** 新建节点
- **THEN** 系统自动生成唯一 id（如 n1/n2 递增），跳过 nodes 中已占用编号，写入文档

#### Scenario: 用户自定义 name
- **WHEN** 用户为节点设置 name
- **THEN** 画布显示该 name，类型以图标/颜色区分而非并入 name；name 为空时显示类型名兜底

#### Scenario: 导入 id 校验
- **WHEN** 导入文档中的节点 id 含非法字符/超长，或 slots/root 引用不存在的 id，或同节点被多个槽位引用
- **THEN** 系统解析校验报错（非法 id / 孤儿引用 / 重复引用），不进入系统
