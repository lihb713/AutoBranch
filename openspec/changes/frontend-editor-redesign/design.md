## Context

现有前端编辑器（嵌套卡片列表 + 单块编辑）无法满足"真实画布 + ref 参数编辑 + 一文档一树"的目标：ref 的 args/returns 在编辑器打开保存时静默丢失（`nodeFromYaml` 只取 ref 目标串）；块声明不可见不可编辑；附属块概念在树形呈现下冗余。详见 proposal.md（Why）。

已充分讨论并固化的完整设计见 `docs/superpowers/specs/2026-09-10-frontend-editor-redesign-design.md`（§1-14）与 **`docs/superpowers/specs/2026-09-11-unified-slot-model-design.md`（统一槽位模型 v2，经用户确认）**。本设计文档记录关键技术决策与理由。

当前代码约束：M2 parser 为"一文档一树 + 仅 Root/Sequence 用 slots、其余字段型"；本变更将其升级为**统一槽位模型**（全部动作走槽位 + Action 叶子 + Condition 概念）；M7 执行器为动态调用（`_tick_ref`）；server 已用 DB-backed resolver；前端 `CanvasTree` 为嵌套卡片。

## Goals / Non-Goals

**Goals:**
- 一文档一树 DSL（`tree`/`nodes`/`root` + 文档级接口），取代多块 DSL
- 真实画布编辑器（节点对象池 + 槽位引用 + 主树/游离区自动布局）
- ref 参数编辑（编辑时自动加载目标文档 inputs/outputs、即时校验）
- 跨文档引用生产可用（文档库：DB-backed resolver + 按名查 API）
- 校验体系（编辑时即时 + 保存汇总 + 导入一次性）

**Non-Goals:**
- 并发节点（Concurrent）——未来类型，节点类型元信息留扩展点
- 前端性能优化（视口裁剪）——当前全量布局
- 视觉设计细节（具体图标/配色/连线样式）——实现期定

## Decisions

### 1. 一文档一树取代多块
**决策**：`tree: <名>` + `nodes:`（节点平铺）+ `root: <id>`；移除 `block`/附属块/`this/块`。
**理由**：树形呈现下"子树 = 节点下加节点"，附属块冗余；`ref: 文档名` 是唯一引用形式，语义统一。
**备选**：保留多块（方案 2）——被弃，树形前端下无必要。

### 2. 节点对象池 + 统一槽位模型（方案 B：平铺 + 语义命名字段引用 id）
**决策**：节点在 `nodes:` 平铺定义；节点间一切动作关联经**语义命名槽位字段**引用子树根节点 id（Root.body / Sequence.actions / Step.action / IfThenElse.then+else / Branch.action+branches[].action / Retry.body / LoopUntil.action）。新增 **Action 叶子节点**（`description`）作为真正叶子；**Condition 为概念性节点**，内嵌为自有字段（Step.expect / IfThenElse.if / Branch.branches[].when / LoopUntil.until）。
**理由**：节点只保留核心语义、动作一律走槽位（用户准则）；直观且统一；前端画布经统一「挂载点」抽象消费（布局/游离判定/删除语义）。
**备选**：① 统一 `slots: {1:id}` 数组——失去语义命名（then/else 无法区分）；② 字段型目标字符串（then/else/body）——旧设计残迹，与"动作一律走槽位"矛盾，被弃。

### 3. 槽位只能选"游离根"
**决策**：容器槽位下拉只展示未被任何槽位引用的节点（游离根）；节点被引用后从游离区移除。
**理由**：自动保证纯树结构（单父、无共享子树成图），不可选项不展示（前端设计法则）。
**备选**：允许引用任意节点——会成图/成环，违反树语义。

### 4. Root 是真实节点类型
**决策**：`type: Root`（固定 1 槽，子限制 1），每文档恰一个，不可删改；顶层 `root: <id>` 引用（id 走统一生成规则）。
**理由**：ref 挂载 = 执行被引文档 Root，语义统一；id 不特殊化（做法乙，兼容导入任意 id）。

### 5. 主树区 + 游离区
**决策**：画布分两区；游离树允许保存（草稿/中途退出）。
**理由**：编辑中未连接的节点可保存，不强制一次性连完；保存校验仅"单根 + 逐树无环"。

### 6. 布局算法
**决策**：固定尺寸节点卡片（类型图标/颜色 + name）；根在上向下生长、兄弟水平均布；自底向上算宽、自顶向下定位；SVG ortho 连线；ref 展开子树嵌入布局；全量布局。
**理由**：固定尺寸简化布局；兄弟水平符合阅读习惯；ref 展开嵌入让引用逻辑在流程中可见。

### 7. 文档库（DB-backed resolver）
**决策**：新增 DB-backed `RefResolver`（按文档名从 DB 加载文档喂给 parser/执行器），替换 server 空 `MappingResolver`；新增 `GET /api/trees/by-name/{name}`；`_tick_ref` 按文档名加载被引文档 Root 执行。
**理由**：一文档一树下跨文档引用是唯一引用路径，生产必须可用；`RefResolver` 抽象已存在，只需补 DB 实现。
**备选**：继续空 resolver——跨文档在生产不可用，与设计矛盾。

### 8. 校验时机分层
**决策**：编辑时即时（必填字段红框、ref 参数对齐/类型匹配）+ 保存汇总（单根/逐树无环/ref 目标存在/配置齐全）+ 导入一次性（解析坏文档）。
**理由**：错误越早越好，节省用户时间；前端即时反馈 + 后端 `/check` 权威兜底。

### 9. 删除/修改语义矩阵
**决策**：删槽位=解引用回游离区；删单节点=子节点各自成游离树；删子树=连带删后代；改槽位=旧节点回游离区。
**理由**：每步结果可预测、无歧义（前端设计法则）。

### 10. 节点 id/name
**决策**：`id` 自动生成（n1/n2...）、导入保留；`name` 用户自定义纯字符串（画布显示名），类型靠图标/颜色区分。
**理由**：文档自包含（可导入导出）；name 不混入类型前缀，用户自由命名。

## Risks / Trade-offs

- [前端编辑器重写范围大（画布/布局/槽位/参数编辑全换）] → Mitigation: 分阶段实施（先文档库与 DSL，再前端画布；每阶段独立可测）。
- [DSL 完全更换为 BREAKING，现有行为树文档全部失效] → Mitigation: 提供导入/迁移工具（旧树形 DSL → 新 nodes/slots）；一次性导入校验。
- [跨文档引用的运行时加载依赖文档库，缺失时引用失败] → Mitigation: 保存/编辑时即校验目标文档存在；运行时明确错误。
- [游离树允许保存可能导致"未完成"文档入库] → Mitigation: 单根 + 逐树无环校验保证结构合法；节点配置校验保证字段齐全（游离树节点也校验）。
- [布局算法对超大树（>100 节点）性能未知] → Mitigation: 当前全量布局接受；后续按需加视口裁剪（非目标）。

## Migration Plan

1. **阶段 1**：文档库（DB-backed resolver + 按名查 API + 跨文档 ref 生产可用）——独立可测，不依赖 DSL 改造。
2. **阶段 2**：DSL 一文档一树（parser `tree`/`nodes`/`root`）+ 迁移工具（旧 → 新）。
3. **阶段 3**：前端画布重写（节点对象池/槽位/主树游离区/布局/ref 参数编辑/校验）。
4. **回滚**：每阶段独立提交；前端与后端 DSL 变更分开，可单独回退。
