## Context

WebOps 引擎由多个可独立交付的模块组成（见 `docs/specs/README.md`）：M2 已产出内部行为树对象与块声明（`BehaviorTree` / `BlockDecl`，仅含基础节点），M3 提供 schema 命名空间的帧管理（`SchemaSpace.enter_block/write/read/resolve_config`），M6 提供叶子执行接口（`execute_leaf(node, ctx) -> LeafResult`），M8 提供报告记录（`Reporter.record_node` 等）。M7 的目标是把这些模块串成确定性编排器（动机见 proposal.md - Why），并满足契约 §5.7/§5.7.7/§5.7.4/§5.9/§12.4 的行为要求（详见 specs/orchestrator/spec.md）。M7 被 M9b 作为库内嵌（§12.3）：后端在同一进程内调用 `engine.run` 并在后台线程驱动，前端每 1 秒轮询执行状态（§12.4）。约束：组合节点零 LLM、遍历阻塞式无 RUNNING、每次 run 全新会话不持久化。

## Goals / Non-Goals

**Goals:**
- 提供一个最小、确定性的遍历器核心，把所有节点类型（Action/Condition/Sequence/Selector/Repeat/Finish + 块引用）统一为可被同一 `tick` 契约驱动的节点
- 保持组合节点纯程序执行，LLM 调用只经由 M6 叶子执行接口发生
- 执行状态可被 M9b 以普通读操作轮询，无需进程间通信
- 以 mock M6 叶子执行为主实现完整可测的遍历/聚合/失败传播逻辑

**Non-Goals:**
- 不实现 LLM 调用本身（归 M6）、不做语义图生成（M4）、不做浏览器底层操作（M1/M5）
- 不做跨运行会话持久化（cookie/登录态复用，契约 §5.9 明确不支持）
- 不做多线程并发遍历（阻塞式单线程语义）
- 不实现 M9b 的 HTTP API 与前端渲染（后续 change）
- 不为"可恢复暂停"引入 RUNNING 状态或可挂起遍历器（契约明确无 RUNNING）

## Decisions

### D1. 遍历器：递归 tick，而非显式栈迭代器

组合节点、叶子、块引用统一实现 `tick()` 并返回 `SUCCESS`/`FAILURE`；Sequence/Selector 递归调用子节点 tick 并按聚合规则短路，Repeat 在循环体内递归调用。使用**递归**而非显式状态机/事件循环，因为遍历是阻塞式且无 RUNNING 状态，无需挂起与恢复。

- 备选 A：基于显式栈的迭代器（`next()` 逐步推进）。可为"暂停/恢复"或流式进度让路，但契约无 RUNNING 状态，且实现复杂度高。
- 备选 B：事件循环/消息驱动的 tick 分发。适合并发/异步叶子，但阻塞式 + 单线程下是过度设计。
- **理由**：递归直接映射行为树结构，代码量与测试面最小；深层树（嵌套块引用/Repeat）有栈深度风险，见 R1。若未来需要流式进度，可在 `ExecState` 层面增加快照而不改遍历模型。

### D2. 执行上下文：单一 `RunContext` 携带共享可变状态

一次 run 的遍历器、schema 命名空间（M3）、报告器（M8）、叶子执行器（M6）、浏览器 context（M1）、执行状态（ExecState）、配置继承链全部挂在同一个 `RunContext` 上，通过构造函数注入依赖（mock 友好），遍历器只与 `RunContext` 交互。

- 备选：全局单例/模块级状态。不可测、不可并发隔离，否决。
- 备选：仅参数透传。遍历递归深度大时签名爆炸，否决。
- **理由**：依赖注入使 mock M6/M8 替换为零成本，满足 M7 测试策略；`ExecState` 作为 RunContext 上的可写对象，供 M9b 同进程轮询。

### D3. 执行状态：遍历器就地更新 + 读侧快照

`ExecState` 作为 RunContext 的一部分被遍历器实时更新：节点进入时写 `current_node`、退出时追加 `completed` 并推进 `progress`（按节点权重累计，如已完成节点数 / 总节点数），`finished` 在根 tick 返回后置位。`get_exec_state()` 返回该对象（或其不可变快照）。

- 备选：报告器（M8）通过回调/事件流间接维护状态。会引入 M8 对遍历进度的耦合，且轮询读取点分散。
- 备选：每次查询时从 M8 报告列表重算。开销小但需额外扫描，且"当前节点"难以还原。
- **理由**：就地更新语义直白，与 §12.4"M7 执行时维护可查询执行状态"逐字对应。线程安全见 R3。

### D4. schema 帧：块引用节点建帧/出块释放

块引用在节点层表现为一个特殊节点（引用块子树）：tick 进入时调用 `SchemaSpace.enter_block` 建帧，执行子树，无论子树 SUCCESS/FAILURE 均在该节点 tick 退出时释放帧。配置参数查找委托给 M3 的 `resolve_config`（自身 → 祖先 → 全局默认）。

- 备选：解析阶段一次性预建所有帧。与"每次块引用建/释放"契约不符，且变量写入顺序难以预知。
- 备选：块引用不释放帧，运行结束后统一清理。内存占用随执行累积，且违反"释放"语义。
- **理由**：动态建/释放与契约 §5.7.4 帧模型一致；利用 M3 的既有能力，M7 只负责调用时机。

### D5. Repeat 模式：loop_until 与 retry 两种循环控制

Repeat 按 M2 产出的 `mode` 分派：
- `loop_until`：每轮先 tick `until`（Condition）→ SUCCESS 则退出；否则 tick body → 下一轮
- `retry`：每轮直接 tick body → SUCCESS 则退出；FAILURE 则下一轮
- 两种模式共用"轮次计数"，到达 `max` 仍不满足退出条件 → 整体 FAILURE

- 备选：把 until 作为循环体内的首个子节点（统一为 retry 模式）。会让 Condition 的失败被当成 body 失败而错误重试，破坏"先判/后判"语义区分。
- **理由**：两种模式唯一差异就是"退出条件的检查时机"，独立实现两段循环控制最忠实于契约 §4.3 的精确语义，也便于表驱动测试。

### D6. 超时：协作式 deadline 下传，而非信号/线程中断

`RunConfig.timeout` 在会话初始化时注入配置继承链（配合 D4）；每个叶子 tick 把生效的 timeout 折算为 deadline 传入 M6 的 `execute_leaf`，由叶子侧在其终止条件（§5.7.2.1 ③）内强制停止该叶子。遍历器侧再兜一层 wall-clock 检查：超时未返回则标记该叶子 FAILURE。

- 备选：`signal.alarm`/线程中断实现硬超时。阻塞在浏览器调用时不可靠（Windows 无 SIGALRM，线程中断无法作用于同步调用），否决。
- 备选：只依赖叶子侧自行遵守。若 M6 侧有 bug 会导致整棵树卡死，故遍历器保留兜底。
- **理由**：协作式 deadline + 遍历器兜底，保证"单叶子超时终止"契约成立且不依赖平台特性。

### D7. 会话初始化：M1 上下文工厂 + 根级注入

`engine.run` 开始时通过注入的浏览器驱动（M1）创建全新 context（无持久化、无历史 cookie），在 SchemaSpace 根级帧写入全局默认配置；解析校验（M2）失败则直接返回修正信息，不启动 context 与遍历；遍历结束（无论成败）统一关闭 context。

- 备选：context 延迟到首个需要浏览器的叶子才创建。省资源但破坏"每次 run 全新会话"的语义清晰性，且报告/初始化时序变复杂。
- **理由**：契约 §5.9 要求每次 run 冷启动，初始化前置、结束时统一释放，生命周期边界清晰。

### D8. 集成形态：同进程同步 `engine.run` + 后台线程宿主

`Engine.run` 保持同步阻塞语义（返回 `RunResult`）；M9b 在后台线程/任务中调用它，主线程通过 `get_exec_state()` 轮询。Engine 自身不管理线程。

- 备选：Engine 内部起线程、返回任务句柄。把调度职责混入引擎，违背"引擎作为库"的定位（§12.3）。
- **理由**：引擎保持纯同步、纯库形态，调度归 M9b，职责清晰且便于独立测试。

## Risks / Trade-offs

- **[R1] 递归栈深度**：深层嵌套块引用或长链 Repeat 展开可能超出 Python 递归上限 → 对重复/嵌套层数设置上限并返回 FAILURE（作为运行期校验），或必要时改为迭代遍历。
- **[R2] 执行状态与 M9b 的并发读**：M9b 后台线程轮询与遍历线程写 `ExecState` 并发 → `get_exec_state()` 返回不可变快照（或对写侧加锁），保证读侧一致性；列表累加用单线程内完成。
- **[R3] 协作式超时的盲区**：M6 若忽略 deadline，遍历器兜底判定可能滞后于真实阻塞 → 遍历器兜底检查同时记录超时警告，仍保证最终该叶子被标记 FAILURE；真正的硬中断超出本模块范围。
- **[R4] 配置继承的边界**：全局默认注入根级 schema 后，"覆盖值只在当前块及以下生效"依赖 M3 解析正确 → 用继承链表驱动测试覆盖块覆盖/祖先/全局默认三级。
- **[R5] mock 与真实执行差距**：mock M6 覆盖遍历逻辑，但真实浏览器 + LLM 叶子存在未预期耗时 → 引擎集成冒烟（可选）以小行为树 + 真实浏览器验证超时与截图链路。
- **[R6] 帧释放后的越权读取**：父块在子块退出后读取已释放帧变量（破坏严格作用域）→ 运行期检测越权访问并报错，报告定位到具体块。

## Migration Plan

本 change 为纯新增模块（引擎编排层），无既有代码迁移。交付顺序：先遍历器核心（mock M6 可跑通），再帧/会话/超时，最后执行状态与报告联动；每个阶段均可在 mock 下独立验证。对既有模块（M2/M3/M6/M8）仅新增调用关系，不改其接口契约，故无需回滚策略。
