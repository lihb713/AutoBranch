## Context

M2 是 WebOps 书写层与执行层的唯一转换点，纯逻辑、无外部运行时依赖（不依赖 LLM、不依赖浏览器）。当前只有 `docs/specs/M2-behavior-tree-parser.md` 模块说明与 `docs/contract.md` §4/§4.3/§4.4、§5.7.3/§5.7.4/§5.7.5 的契约定义，尚未落地实现。需求层面见 `proposal.md` 与 `specs/behavior-tree-parser/spec.md`。项目为独立 conda 环境（`webops`，Python 3.11）下的 Python 包，随 `pip install -e .` 安装；本模块被 M7（编排器）、M9b（后端）与 M3（schema 命名空间）依赖。

## Goals / Non-Goals

**Goals:**
- 单一解析入口 `parse(doc, ref_resolver) -> ParseResult`，输出纯基础节点行为树、块声明表与校验报告。
- 复合节点展开、块引用解析、schema 声明提取、配置参数覆盖识别全部为确定性纯函数。
- 清晰度校验逐类可独立触发、错误清单可读可定位。
- 全量测试不依赖 LLM / 浏览器，可独立运行。

**Non-Goals:**
- 不实现引擎遍历/执行（M7 范围）。
- 不实现 schema 命名空间的运行时求值（M3 范围）；本模块只提取声明与绑定关系。
- 不实现 LLM 归约、定位或验证（M6 / 语义图范围）。
- 不做文档的版本迁移或向后兼容旧格式（当前尚无已发布格式）。

## Decisions

### D1: 两阶段流水线：解析 → 展开与校验
先做「结构解析」得到带复合节点与引用的中间表示，再做「规范化」统一展开复合节点、解析引用、提取声明并执行校验，最后产出纯基础节点行为树。理由：复合节点展开需要已解析的完整结构上下文，而引用解析需要在展开前完成以建立 schema 命名空间；两阶段使错误定位更精确（结构错 vs 语义错）。备选：单遍递归解析（混合展开与引用解析）——实现更简但错误上下文不完整、可读错误难构造。

### D2: 引用解析通过 `RefResolver` 接口注入，模块自身不感知存储
`parse` 接受 `ref_resolver: RefResolver`，模块只依赖「给定文档标识与块名 → 返回该块文档源」的抽象接口。理由：M2 为纯逻辑模块，不应绑定文件系统/后端存储；M7 执行时可注入真实解析器，测试时可注入 fixture 解析器，从而支撑跨文档 fixture 测试。备选：内置文件系统加载器——简单但破坏纯逻辑边界、测试需真实文件。

### D3: 复合节点展开规则集中为一张表驱动映射
Step/Branch/LoopUntil/Retry/IfThenElse 的展开语义（对应 `docs/contract.md` §4.3）集中在单一展开规则映射中，输入中间节点、输出基础节点组合。理由：展开规则即契约（§4.3 精确语义），集中表达使表驱动测试可直接覆盖每一种复合节点的多组样例，且契约变更只改一处。备选：在各复合节点类型上分散展开——实现分散、契约对应关系不直观。

### D4: 校验器按校验类别拆分为独立规则，汇总为 `CheckReport`
清晰度校验（§4.4 八类：结构、展开、引用、循环上界、变量契约、可定位、验证条件、谓词可校验）各自独立实现、可单独触发，最终汇总为统一 `CheckReport`（通过/失败 + 错误清单）。理由：M2 spec 验收要求「对每类违规构造反例，验证正确报错」，独立规则使反例矩阵测试可直接映射到规则；错误清单逐条可读可定位（含文档位置与违反规则）。备选：单一巨型校验函数——实现快但难测试、错误信息粗糙。

### D5: 声明提取与配置参数覆盖随解析一并产出，不另设遍历
块声明表（输入/输出）在解析命名块时同步提取；配置参数覆盖在块 schema 下识别并标注生效范围（当前块及子树），未声明则回落全局默认（由执行层处理）。理由：两者都是书写层信息的直接投影，一次遍历即可完成，避免对文档的二次扫描。备选：解析后独立扫描声明——逻辑重复、且需再次理解嵌套结构。

## Risks / Trade-offs

- [跨文档引用形成环] → 引用解析建立 schema 命名空间时记录解析栈，检测到循环引用（A 引用 B、B 又引用 A）时判定校验失败并报告环路。
- [YAML 语义与 dict 输入差异（别名、多文档流）] → 解析层统一把 yaml 文本先转为 dict 再走同一解析路径，保证两种输入行为一致；用 fixture 覆盖别名与多文档场景。
- [展开后行为树规模膨胀（深嵌套复合节点）] → 展开深度受限 + 递归上限，超过即校验失败；展开结果仅存于内存，不持久化。
- [变量可见性校验需与 M3 命名空间规则严格一致] → 以 `docs/contract.md` §5.3/§5.7.4 的「只读写自己的 schema 与直接子块」为唯一规则来源，校验逻辑单点实现，避免两处漂移。

## Migration Plan

本 change 为新增模块，无既有实现可迁移。落地时在 `webops` conda 环境执行 `pip install -e .` 注册包入口，以 `pytest` 运行单元测试、以 `pytest -m integration` 运行含真实引用解析器的集成测试。回滚策略：未发布版本，直接移除模块文件即可，无数据/兼容负担。
