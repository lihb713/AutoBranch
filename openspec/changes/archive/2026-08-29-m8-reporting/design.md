## Context

WebOps 引擎确定性地遍历行为树（M7 编排器），在叶子节点内执行有界 LLM 代理（M6）。当前引擎不记录执行过程，M9b 需向前端轮询展示执行进度/节点结果/截图（§12.4）。本 change 为阶段 2 的独立模块 M8（详见 proposal.md —— Why），仅在 M7 整合前交付报告能力，与 M1（截图）、M6（LeafTrace）存在数据依赖。约束：M8 须可独立开发与测试（mock M1/M6/M7 数据），不依赖真实浏览器与 LLM 执行。

## Goals / Non-Goals

**Goals:**
- 定义 `Reporter` 记录接口（`record_node` / `capture_screenshot` / `finalize`）与 `NodeReport` 数据结构，供 M7 调用。
- 提供生成两份报告（执行报告含截图 / 回溯报告含 LLM 推理）的能力与持久化存储。
- 提供可查询的 `ExecState`（进度/当前节点/已完成报告/完成标记），供 M9b 轮询。
- 全部数据源（节点执行数据、截图、LeafTrace）可 mock，测试不依赖真实浏览器/LLM。

**Non-Goals:**
- 不实现行为树遍历与叶子执行本身（属 M7/M6 范围），M8 只被动记录。
- 不实现 HTTP 服务与前端渲染（属 M9b/M9a 范围），M8 只负责持久化与路径提供。
- 不决定截图/报告的展示格式与交互，只保证内容完整、格式清晰可读。
- 不处理跨运行登录态/会话复用的可复现性问题（属 §5.9）。

## Decisions

- **决策 1：Reporter 为被动记录器（记录 + 查询 + finalize），而非主动采集器**
  由 M7 在每个节点退出前调用 `record_node`、在叶子返回前调用 `capture_screenshot`；M8 不主动 hook 遍历器。
  理由：与契约 §5.8.3「节点退出前记录 / 返回前截图」的时机语义一致，M8 保持单方向依赖、可独立测试；M7 掌握节点生命周期，天然是记录触发者。
  备选：M8 内嵌遍历器 hook——会增加 M8 对行为树结构的依赖，破坏模块独立性，否决。

- **决策 2：`NodeReport` 用「字段 + 可空专有字段」承载 Action/Condition/复合节点差异**
  `action_call`（Action 专有）、`condition_result`（Condition 专有）、`screenshot_path`（Action/Condition 专有）、`llm_trace`（回溯报告专用）均为可空字段，单一结构覆盖三类节点。
  理由：与模块 spec §5.1 的 `NodeReport` 契约一致；避免按节点类型分支多个报告结构，两份报告生成时只需按需读取字段。
  备选：按节点类型拆分子类结构——增加类型分支复杂度，且报告生成需多态处理，否决。

- **决策 3：`ExecState` 与报告记录共用同一数据源，finalize 从累积记录派生两份报告**
  执行期间 `ExecState.completed` 即已记录的 `NodeReport` 列表，`progress` 由完成节点数/总节点数计算；`finalize` 基于全部节点报告生成执行报告与回溯报告。
  理由：与 §12.4「M7 执行时维护可查询执行状态」一致；避免状态与报告两套数据不一致，单数据源保证轮询与最终报告始终一致。
  备选：执行状态与报告各自独立维护——存在中间态不一致风险，否决。

- **决策 4：截图在 `capture_screenshot` 时即落盘，报告记录引用路径而非内嵌数据**
  截图文件持久化在存储目录，`NodeReport.screenshot_path` 只存路径；报告文件（执行/回溯）在 `finalize` 时生成并落盘，均与 `run_id` 关联。
  理由：与 §12.4「截图路径」「报告文件可经 HTTP 提供」的消费方式一致；路径引用避免报告体积膨胀，也便于 M9b 直接提供静态文件。
  备选：报告内嵌 Base64 截图——报告体积大、无法直接以文件形式提供，否决。

- **决策 5：存储布局按 `run_id` 归组**
  存储目录结构为 `<run_id>/<node_index>_<desc>.png`、`<run_id>/exec_report.md`、`<run_id>/trace_report.md` 等，外部按 run_id 可整体提供。
  理由：满足「报告/截图路径与 run_id 关联，供 M9b 提供」的需求，单运行内容集中便于清理与归档。
  备选：全局平铺文件名——跨运行难关联、易冲突，否决。

## Risks / Trade-offs

- [截图失败（页面关闭/浏览器崩溃）] → 截图异常被捕获并记录，节点报告截图路径置空，执行与记录不中断；finalize 容忍缺失截图。
- [程序侧致命错误终止流程] → 已记录的节点报告与截图先持久化再终止（finalize 在终止路径上被调用），报告不丢已发生节点。
- [报告/截图体积增长与存储清理] → 非目标：由 M9b 侧提供生命周期管理；M8 只保证按 run_id 可定位、可替换。
- [进度计算依赖总节点数] → 树中节点总数在执行前已知（M2 解析产物），若统计口径与 M7 遍历不一致，进度可能偏离——以「已完成节点数/总节点数」为唯一口径，并在集成测试中对照验证。
- [LeafTrace 可能为 None（复合节点/未触发 LLM）] → 回溯报告对无推理节点省略 LLM 段，仅保留执行详情，契约要求不中断。

## Migration Plan

- 无既有实现可迁移：本 change 首次引入 `reporting` capability，作为独立模块落地，不修改现有引擎遍历逻辑，M7 整合时再接入 `Reporter` 调用点。
- 回滚：删除新增报告模块与其对 M1/M6 数据类型的引用即可，不涉及现有功能变更。

## Open Questions

- 无：执行状态的轮询间隔、HTTP 路径映射等属 M9b/M9a 决策，不影响 M8 的数据契约与任务分解。
