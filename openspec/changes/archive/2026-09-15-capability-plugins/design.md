## Context

当前系统以浏览器为中心：M5 引擎函数层（`EngineFunctions`）硬编码浏览器工具，`call()` 只认 `ENGINE_TOOLS`；M1 浏览器驱动、M4 语义图是独立模块；M3 内置 `page_ref` 类型与页面变量机制；M6 叶子执行强制预取语义图、工具直接写变量；M8 报告硬编码 `page_url`/`screenshot`。详见 `proposal.md`（Why）。

本设计基于探索讨论（完整思考记录见 `docs/tmp/capability-expansion-design.md`）。

## Goals / Non-Goals

**Goals:**
- 引擎核心与"浏览器/页面"解耦，浏览器降格为插件。
- 统一函数注册表：同一批函数服务 LLM 工具（描述驱动）与 FunctionCall（确定性调用）。
- 插件框架：插件类 + FunctionDef + 两级能力选择 + 懒装配 + 统一分发/报告接口。
- 变量读写归引擎、插件只返回值；泛型对象类型。
- 模块按新架构重编排（M0–M9）。

**Non-Goals:**
- 不做安全机制（权限/白名单/确认）——插件由内部开发者提供。
- 不做"幂等/重试"声明——重试由行为树 `Retry` 节点控制。
- 不支持用户自定义插件引入三方库 / 自定义库（仅标准库）。
- 不做插件依赖自动识别 / 安装。

## Decisions

### D1. 统一函数注册表（两种使用方式并存）
**决策**：引入统一函数注册表。同一批函数既作为 LLM 工具（描述驱动，分叉 A），也可被 FunctionCall 节点直接调用（确定性，分叉 B）。
**理由**：即使操作确定（如乘 2），用自然语言描述获取结果仍需 LLM 理解并调用；而一系列确定操作直接写成函数更简洁。两者共享底层函数。
**备选**：仅 LLM 工具（牺牲确定性）；仅函数调用（牺牲自然语言灵活性）。

### D2. FunctionCall 节点（≈ ref 的"函数版"）
**决策**：新增 `type: function` 节点：`function` + `args`（列表，按序对应函数入参）+ `returns`（字典，接收名→类型，按序对应多返回值）；运行期确定性调用（不经 LLM），异常 = 节点 FAILURE。
**理由**：与 ref 同构（ref 调文档、FunctionCall 调函数），复用 args/returns/帧机制。
**备选**：新节点语义差异大（不必要）。

### D3. 插件模型：插件类 + 结构化 FunctionDef
**决策**：插件 = 插件类（`name`/`description`/`function_defs()`/`init(runtime)`/`call()`）+ 结构化 `FunctionDef`（名字/说明/参数/多返回值/变量目标参数 `output_param`/实现）。函数经显式标注（`@engine_function`）注册；未标注不注册。
**理由**：`description` 供能力概览，`FunctionDef` 供工具 schema 与校验；显式注册区分对外函数与内部辅助。
**备选**：薄接口（tools/call）——不足以承载签名/多返回值/产出型标注。

### D4. 引擎核心 / 插件框架 / 插件 三层
**决策**：引擎核心（解析/遍历/流程/ref/FunctionCall/报告/LLM/变量读写）；插件框架（注册表/懒装配/`use_capability`/分发/统一报告接口）；具体插件（浏览器/计算/SSH/文件/自定义）。`use_capability` 属框架，不属任何具体插件。
**理由**：判断标准——操作"行为树自身状态"归核心；操作"外部能力"归插件。

### D5. 变量读写归引擎，插件只返回值
**决策**：插件函数只返回值（业务值 + 报告附加信息），不接触 `space`/`frame`。变量写入由引擎落笔：产出型工具（`FunctionDef.output_param` 声明变量目标参数）由叶子执行器拆出目标、调用函数、写变量。
**理由**：变量空间属行为树设计；插件应纯功能。与"ref 返回帧隔离"一致。
**备选**：插件直接写变量（当前 M5 现状，耦合行为树状态，被否）。

### D6. 两级能力选择 + 懒装配
**决策**：① 能力概览 + 框架工具 `use_capability(name)`；② LLM 选能力 → 引擎 `init` 插件 → 函数追加工具集 → LLM 细选。选能力复用 `tool_calls`，无新输出协议。懒装配在调用分发时触发；重资源 run 内首次用到才启动、run 结束释放。去叶子强制语义图预取（改 prompt 强调 LLM 自行获取最新语义图）。
**理由**：两级候选更少，LLM 选择更准；懒装配省资源（纯计算行为树零浏览器开销）。

### D7. 泛型对象类型（page_ref 纳入）
**决策**：类型系统加泛型对象类型 `object`（不校验，`str(value)` 呈现）；`page_ref` 纳入泛型（浏览器插件的对象）；引擎核心不再有页面概念。变量声明写 `object`，实际类型由函数返回值决定，引擎记录（函数声明返回类型）供黑板/报告展示。
**理由**：用户不必记插件对象类型；类型安全落在函数签名层。
**备选**：每种对象一个 token（耦合、累）。

### D8. 插件驱动的报告
**决策**：报告 = 引擎基础字段（node_type/desc/result/timestamp/action_call/llm_trace）+ 插件附加（`FunctionResult.report`，引擎落笔，统一结构化接口）。截图在 `semantic_graph` 时由浏览器插件产出；不再由编排器无条件截。
**理由**：不硬编码能力专属字段；与变量落笔同构。

### D9. 插件来源与组织
**决策**：预置插件（文件系统 `plugins/` 包，启动扫描 + import，可依赖 `common` + 三方库）；用户自定义插件（源码存 DB，`compile + exec`，仅标准库）；`common` 为共享库（非插件）。`plugins/` 唯一目录，无 `custom/` 子目录。
**理由**：预置走文件自然；自定义走 DB 便于 Web 编辑 + 重载（无 import 缓存）。插件由开发者维护，不对外开放。

### D10. 插件管理（前端 + 后端）
**决策**：后端插件 API（CRUD + 校验 + 关联查询）+ `plugin` 表（`kind`: builtin|custom）；前端管理页（列表 + CodeMirror 6 编辑器 + 保存校验 + 删除关联提示）；删除后引用该插件的 FunctionCall `function` 置空 + 校验报"悬空引用"。
**理由**：把插件开发从"改文件 + 重启"变为"Web 编辑 + 即时生效"。

### D11. 模块重编排（BREAKING）
**决策**：引擎核心 M0 LLM / M1 解析 / M2 变量空间 / M3 插件框架 / M4 叶子 agent / M5 编排器 / M6 报告；M7 插件集；M8 管理后端；M9 前端。浏览器驱动 + 语义图并入浏览器插件（M7）；移除独立浏览器驱动 / 语义图 / M5 引擎函数层。
**理由**：按新架构重排，不为兼容保留旧编号。

### D12. 不做安全机制 / 重试声明
**决策**：无危险标记、无确认、无权限；无幂等/重试声明。
**理由**：内部工具，插件由内部开发者提供。

## Risks / Trade-offs

- [大规模 BREAKING 重构（M5/浏览器驱动/语义图移除，模块重排）] → Mitigation: 分阶段实施（插件框架 → 浏览器插件迁移 → FunctionCall → 前端管理），每阶段可测；OpenSpec tasks 分批次。
- [两级能力选择增加一次 LLM 交互] → Mitigation: 准确性优先；概览精简（各能力一句）。
- [泛型 `object` 类型牺牲变量层类型安全] → Mitigation: 类型约束下沉到函数签名；引擎记录实际类型供展示。
- [DB 源码 + exec 的动态执行] → Mitigation: 仅开发者提供（信任）；校验约束（仅标准库）。
- [自定义插件仅标准库限制功能] → Mitigation: 复杂能力走预置插件；后续有需求再议。

## Migration Plan

1. **插件框架（M3）**：注册表 / 插件类 / FunctionDef / 懒装配 / use_capability / 分发 / 报告接口。
2. **浏览器插件（M7）**：把 M1 驱动 + M4 语义图 + M5 浏览器函数迁入浏览器插件。
3. **解析器（M1）**：FunctionCall 节点 + 泛型类型。
4. **叶子 agent（M4）+ 编排器（M5）**：两级能力选择 + 变量落笔 + 报告插件驱动。
5. **插件管理（M8/M9）**：后端 API + 插件表 + 前端管理页。
6. **文档同步**：`docs/contract.md`、`docs/specs/` 按新模块重编排。
