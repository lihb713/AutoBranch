## Context

M5 是暴露给 LLM 的引擎函数层（见 proposal.md - Why）。契约依据：`docs/contract.md` §5.8/§5.8.1（引擎执行基础设施与函数集）、§5.8.2（HTTP 接口两形态）、§5.10（页面变量机制）、§8.8（semantic_graph 接口）、§5.3/§5.3.5（变量写入与类型契约）、§7.8（ref 桥，倾向方案 B）。当前约束：M1 浏览器驱动提供操作/文件/HTTP/DOM 爬取实现，M4 提供 `semantic_graph(范围, LOD)` 接口，M3 提供变量读写、页面变量绑定与类型校验；M5 把这些能力收敛为 LLM 可调用的函数集。M5 不包含报告与流程流转（属 M8/M7），`finish` 不是引擎函数。

## Goals / Non-Goals

**Goals:**
- 单一入口：`ENGINE_TOOLS`（工具 schema 列表）+ `EngineFunctions`（执行实现）配对暴露，M6 一个入口即可完成"声明工具 → 执行工具"
- 确定性优先：ref 解析全程确定性、不信任 LLM；页面操作绑定由当前页面变量决定，LLM 无页面切换决策
- 错误语义分层：普通失败以 `OpResult(ok=False)` 回传 LLM 保持 agent 会话，致命错误抛 `FatalBrowserError` 终止流程
- 可测试：以 mock M4/M3/M1 为主独立测试，不依赖 M6/M7
- 可扩展：新增函数仅需"实现 + 注册"，不改既有代码

**Non-Goals:**
- 不实现报告记录与截图（M8 负责，M5 只返回 OpResult）
- 不实现页面切换决策与多标签页语义（引擎内部机制，LLM 只面对当前页面变量的语义图）
- 不实现浏览器会话生命周期与 cookie 持久化（M1/§5.9 负责）
- 不做跨 iframe 操作与动态加载元素支持（§8.9 明确排除）
- 不做 LLM 推理循环本身（M6 负责，M5 只提供单个函数的一次调用）

## Decisions

### D1: 工具 schema 与执行实现分离（声明式注册表）

`ENGINE_TOOLS` 是纯声明（每个函数一个 `ToolSpec`：name + description + parameters JSON Schema），`EngineFunctions` 是执行实现，两者通过同一函数名配对。M6 把 `ENGINE_TOOLS` 传给 M0 会话作为工具定义，收到工具调用后按名字分发到 `EngineFunctions` 对应方法。

- 备选：把 schema 与实现耦合在单个对象里。否决——工具 schema 是给 LLM 的契约，实现是引擎内部细节，分离使两者可独立演进（改实现不动 schema，反之亦然），且"注册表可扩展"只需向列表追加一项。
- 理由：与 M0 的 ToolSpec 结构（name/description/parameters）直接对齐，M6 零转换。

### D2: ref 解析采用"会话内即用即弃"（契约 §7.8 方案 B）

LLM 每次动作前必须先取最新快照（语义图），用最新 ref；引擎维护 ref 映射表（ref ↔ 元素 id ↔ DOM 节点），页面状态一变化即作废旧 ref，旧 ref 调用被拒绝返回 `OpResult(ok=False)`。

- 备选 A（稳定 ref，DOM 特征跟踪元素身份）：需要身份跟踪，动态页面易错，与确定性原则相悖。否决。
- 理由：方案 B 与"元素定位运行时实时做、不编译期缓存"一致，无身份跟踪负担，确定性最高。LLM 不跨快照记忆，行为可预测。
- 实现要点：ref 映射表与当前语义图快照绑定；语义图每次完整生成（无缓存），其生成即刷新映射表并作废旧 ref。

### D3: 页面操作绑定 = 当前页面变量

`EngineFunctions` 构造时注入"当前页面变量"的读写通道（来自 M3），操作类函数在执行前从当前页面变量解析出目标 page 对象（来自 M1）。页面切换只发生在变量被写入新的页面引用时。

- 备选：函数参数显式传页。否决——契约 §5.10 明确规定操作绑定由当前页面变量决定、LLM 不做切换决策，显式传页会把多标签页概念暴露给 LLM。
- 理由：LLM 永远只面对"当前页面变量的语义图"（一页），引擎内部管理多页，符合契约并降低 LLM 负担。

### D4: 错误语义两级（OpResult 回传 vs FatalBrowserError）

所有普通失败（click 失败、ref 无效/过期、类型校验失败、无匹配请求、无当前页面等）统一返回 `OpResult(ok=False, error=...)`，构造时不抛异常；仅致命错误（浏览器崩溃、浏览器进程不可用、页面上下文销毁等 M1 层的不可恢复异常）包装为 `FatalBrowserError` 抛出。

- 备选：所有失败都抛异常。否决——agent 语义下 LLM 需从失败中自行修正，抛异常会中断会话，违背契约 §5.8。
- 理由：两级语义正好对应"LLM 可修正"与"无法继续"两类情形；M5 在函数边界捕获 M1 的底层异常并分类：可恢复 → OpResult，不可恢复 → FatalBrowserError。

### D5: 变量写入副作用经由 M3，类型校验前置

`open` 把页面引用写入 M3 页面引用类型变量；`extract` 读取目标元素文本/属性/值，写入目标变量前先经 M3 类型校验，不匹配则不写并返回失败。

- 备选：M5 自行管理变量写入。否决——违反契约 §5.3/§5.3.5，会绕过 M3 的命名空间与类型契约，破坏一致性。
- 理由：M3 是变量读写与类型校验的唯一权威，M5 只做"提取值"与"传参"，写入与校验全部委托 M3。

### D6: 函数级依赖注入便于独立测试

`EngineFunctions` 依赖的 M1/M4/M3 能力以构造注入方式提供（接口约定，而非硬编码引用），使单测可用 mock 替换：mock 语义图、mock 变量读写、mock 浏览器。函数集扩展仅需在注册表追加并实现同名方法。

- 备选：模块级全局单例。否决——难以隔离测试，违背"测试以 mock 为主、不依赖 M6/M7"的验收。
- 理由：依赖注入保证 M5 独立于 M6/M7 可测，也是函数可扩展性的前提。

## Risks / Trade-offs

- **ref 即用即弃增加 LLM 调用开销** → LLM 每次动作前必须重新取语义图（新 ref），轮次增多、token 增加。缓解：语义图 LOD 分级（§9.5）控制信息量；这是确定性换取开销的既定权衡，与契约一致。
- **页面操作绑定隐藏多页语义，调试变难** → 跨页数据全走变量，出错时难以在日志中直接看到"操作了哪个页"。缓解：OpResult 附当前页面引用标识（可读信息），报告由 M8 记录 URL。
- **M1 异常分类边界模糊** → "可恢复/致命"如何划分存在灰色地带。缓解：以"浏览器进程/页面上下文是否仍可用"为判据；仍存疑的先归为可恢复（OpResult），宁可让 LLM 修正也不误杀流程。
- **HTTP 形态 B 无自动认证** → 独立请求需用户在流程中显式提供认证信息，跨请求无 cookie 保持。缓解：这是契约 §5.8.2 的明确设计（可复现性优先），文档与工具描述中提示用户经变量传认证。

## Migration Plan

- 本 change 为新增模块，无既有代码迁移；按模块实施顺序（阶段 3）在 M1/M4/M3 就绪后接入。
- 回滚策略：M5 为独立新增包，依赖注入式接入，M6/M7 尚未依赖时可直接移除，不影响既有模块。

## Open Questions

- 无。所有影响 spec/实现/任务拆分的不确定点（ref 策略、绑定语义、错误分级、HTTP 形态）均已在契约中明确，本 design 据此落定，无需推迟决策。
