# reporting Specification

## Purpose

记录行为树执行过程：所有节点退出前记录执行情况，Action/Condition 返回前截图页面状态，生成执行报告（每节点结果 + 截图）与回溯报告（执行详情 + LLM 推理，不含截图）两份报告，并提供可查询的执行状态与持久化的报告/截图，供编排器记录、管理系统展示与用户回溯排查。

## Requirements

### Requirement: 所有节点退出前记录执行情况

系统 SHALL 在行为树中每个节点（含复合节点与叶子节点）退出前记录该节点的执行情况，生成节点报告，其内容包含：节点类型、节点描述、执行结果（SUCCESS/FAILURE）、Action 节点的引擎函数调用记录（调用了哪个函数、是否成功）、Condition 节点的判断结果（布尔值）、时间、页面 URL。节点报告 SHALL 可被持久化并作为执行状态的一部分提供。

#### Scenario: 复合节点退出前记录执行情况

- **WHEN** 编排器遍历至一个 Sequence/Selector 等复合节点，该节点执行完毕即将退出
- **THEN** 系统记录该节点的节点报告，包含节点类型、节点描述、执行结果与时间

#### Scenario: Action 节点退出前记录函数调用

- **WHEN** 一个 Action 节点执行完成，该叶子节点调用过引擎函数
- **THEN** 节点报告包含 Action 专有的调用记录：调用了哪个引擎函数以及是否成功

#### Scenario: Condition 节点退出前记录判断结果

- **WHEN** 一个 Condition 节点执行完成返回布尔判断
- **THEN** 节点报告包含 Condition 专有的判断结果（布尔值）

#### Scenario: 执行失败的节点同样被记录

- **WHEN** 任意节点以 FAILURE 退出（含叶子终止条件触发的 LLM 侧失败）
- **THEN** 系统仍记录该节点的执行情况，执行结果为 FAILURE，报告过程不中断

### Requirement: Action/Condition 节点返回前截图

系统 SHALL 在 Action 或 Condition 节点返回之前截图当前页面状态（经 M1 截图能力），并把截图路径关联到该节点的执行报告中。截图动作失败时，SHALL 记录失败情况，节点报告截图路径为空，且不影响节点执行结果与后续记录。

#### Scenario: Action 节点返回前截图

- **WHEN** 一个 Action 节点即将返回
- **THEN** 系统在返回前截图当前页面状态，并将截图路径写入该节点的执行报告

#### Scenario: Condition 节点返回前截图

- **WHEN** 一个 Condition 节点即将返回
- **THEN** 系统在返回前截图当前页面状态，并将截图路径写入该节点的执行报告

#### Scenario: 截图失败不影响节点记录

- **WHEN** Action/Condition 节点返回前截图失败（如页面已关闭）
- **THEN** 系统记录截图失败情况，该节点执行报告的截图路径为空，节点执行结果与执行情况记录不受影响

#### Scenario: 复合节点不触发截图

- **WHEN** 复合节点（非 Action/Condition）退出
- **THEN** 系统仅记录执行情况，不触发截图，其执行报告无截图

### Requirement: 生成执行报告

系统 SHALL 在流程结束时生成执行报告（报告①），汇总每个节点的执行结果并包含截图：每个节点列出节点类型、节点描述、执行结果（SUCCESS/FAILURE）、Action 的函数调用、Condition 的判断结果、时间、页面 URL，以及 Action/Condition 节点的页面截图。执行报告用于概览整个流程的执行结果，SHALL 不含 LLM 推理过程。

#### Scenario: 执行报告包含每节点结果与截图

- **WHEN** 行为树执行完毕，系统生成执行报告
- **THEN** 报告中每个节点包含节点类型、描述、执行结果、时间、URL，且 Action/Condition 节点包含对应截图

#### Scenario: 执行报告反映节点成功与失败

- **WHEN** 流程中部分节点 SUCCESS、部分节点 FAILURE
- **THEN** 执行报告如实汇总每个节点的结果，成功与失败节点均可被区分

#### Scenario: 执行报告不包含 LLM 推理

- **WHEN** 执行报告中含 LLM 推理的节点执行完毕
- **THEN** 执行报告不包含任何节点的 LLM 输入、推理过程或决策结果内容

#### Scenario: 执行报告可读格式清晰

- **WHEN** 执行报告生成完毕
- **THEN** 报告格式清晰、按节点顺序组织，可直接展示或经 M9b 提供

### Requirement: 生成回溯报告

系统 SHALL 在流程结束时生成回溯报告（报告②），汇总每个节点的详细执行情况，并补充该节点调用 LLM 时的推理过程：提供给 LLM 的输入（节点描述 + 语义图）、LLM 的推理过程（选择的函数/判断依据）、LLM 的决策结果。回溯报告 SHALL 不含任何截图，用于深挖问题回溯。

#### Scenario: 回溯报告包含 LLM 输入、推理过程与决策结果

- **WHEN** 叶子节点执行时调用了 LLM，流程结束后生成回溯报告
- **THEN** 该节点的回溯条目包含 LLM 输入、推理过程与决策结果

#### Scenario: 回溯报告不包含截图

- **WHEN** 流程结束生成回溯报告，且执行过程中产生过截图
- **THEN** 回溯报告不含任何截图或其路径

#### Scenario: 未调用 LLM 的节点不产生推理条目

- **WHEN** 复合节点或未触发 LLM 的叶子节点执行完毕
- **THEN** 回溯报告中该节点的条目只含执行详情，无 LLM 推理部分

#### Scenario: 回溯报告按节点顺序组织

- **WHEN** 回溯报告生成完毕
- **THEN** 报告按节点执行顺序组织，与执行报告节点一致，便于对照回溯

### Requirement: 提供可查询的执行状态

系统 SHALL 维护并对外提供可查询的执行状态，包含：运行标识 run_id、执行进度（0.0 ~ 1.0）、当前执行节点、已完成节点的报告列表、完成标记。执行状态 SHALL 随节点执行实时更新，供管理系统（M9b）定时轮询，轮询不改变执行本身。

#### Scenario: 执行中可查询进度与当前节点

- **WHEN** 流程执行中，外部查询执行状态
- **THEN** 状态返回正确的 run_id、进度（0.0 ~ 1.0）与当前执行节点

#### Scenario: 节点完成使已完成报告累积

- **WHEN** 一个节点执行完毕
- **THEN** 执行状态中的已完成节点报告列表追加该节点报告，进度随之推进

#### Scenario: 执行完毕标记完成

- **WHEN** 流程执行完毕（成功或失败终止）
- **THEN** 执行状态的完成标记为真，进度为 1.0，已完成报告包含全部节点

#### Scenario: 轮询执行状态不干扰执行

- **WHEN** 外部在流程执行期间多次轮询执行状态
- **THEN** 每次返回的状态一致且正确，轮询动作不影响节点执行与报告记录

### Requirement: 报告与截图持久化

系统 SHALL 将截图与执行报告、回溯报告持久化到存储，并提供可被管理系统（M9b）访问的路径。报告与截图 SHALL 与运行标识 run_id 相关联，供执行结束后提供完整报告。

#### Scenario: 截图写入持久化目录

- **WHEN** Action/Condition 节点返回前完成截图
- **THEN** 截图文件写入持久化目录，路径可被系统外部（M9b）访问

#### Scenario: 两份报告写入持久化目录

- **WHEN** 流程结束生成执行报告与回溯报告
- **THEN** 两份报告写入持久化目录，路径与对应 run_id 关联，可被系统外部访问

#### Scenario: 同一运行的报告与截图可被关联提供

- **WHEN** 外部按 run_id 请求报告与截图
- **THEN** 执行报告、回溯报告及该运行的所有截图均可经持久化路径提供

#### Scenario: 报告不因执行异常丢失

- **WHEN** 流程因叶子失败或程序侧致命错误终止
- **THEN** 已记录的执行情况与截图仍被持久化，最终报告包含已发生的全部节点记录
