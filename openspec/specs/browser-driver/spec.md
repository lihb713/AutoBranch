# browser-driver Specification

## Purpose

为 WebOps 提供唯一接触真实浏览器的底层能力：管理每次运行的浏览器会话与多页面引用，在指定页面上执行操作、文件、HTTP 与截图函数，并向 M4 输出 DOM 爬取快照。

## Requirements

### Requirement: 浏览器会话生命周期与冷启动

系统 SHALL 在每次 run 开始时创建全新的浏览器 context，该 context 无任何历史 cookie/登录态，全流程共享、跨运行不持久化；在 run 结束时完整释放 context 与全部页面。

#### Scenario: 每次 start 均为冷启动
- **WHEN** 在同一配置下连续两次创建会话
- **THEN** 第二次会话不含第一次会话产生的任何 cookie、localStorage 或登录态

#### Scenario: 全流程共享同一 context
- **WHEN** 在一次会话生命周期内多次打开页面
- **THEN** 所有页面共享同一个 context，共享同一会话 cookie 空间

#### Scenario: 会话结束释放全部资源
- **WHEN** 会话被显式结束
- **THEN** context 与全部已打开页面被释放，此前返回的页面引用不再可用于操作

### Requirement: 页面打开与页面引用

系统 SHALL 提供打开页面能力：打开一个 URL 时返回该页面的页面引用（PageRef）；同一会话内可打开多个页面并存。

#### Scenario: 打开页面返回引用
- **WHEN** 打开一个可达的 URL
- **THEN** 返回一个页面引用，且该引用对应的页面已加载目标 URL

#### Scenario: 多页并存互不干扰
- **WHEN** 在同一会话内连续打开两个不同的 URL
- **THEN** 返回两个独立的页面引用，分别对应两个独立页面，各自加载各自 URL

#### Scenario: 打开不可达页面失败
- **WHEN** 打开的目标地址不可达或超过超时阈值
- **THEN** 返回失败结果并携带错误信息，不产出可用页面引用

### Requirement: 页面引用与操作绑定

系统 SHALL 让所有页面操作都显式作用于调用方指定的页面引用；页面引用无效时操作不得静默作用于其他页面。

#### Scenario: 操作作用于指定页
- **WHEN** 两个页面并存，且调用方对页面 A 的引用执行点击操作
- **THEN** 该操作只影响页面 A，页面 B 的状态不变

#### Scenario: 无效引用返回失败
- **WHEN** 对已释放或从未存在的页面引用执行操作
- **THEN** 返回失败结果并携带错误信息

### Requirement: 页面操作函数

系统 SHALL 在指定页面上提供 click、type、select、check、uncheck、scroll、wait 等操作函数，且每一类操作在真实浏览器上可执行；元素操作失败时返回携带错误信息的失败结果。

#### Scenario: 点击元素
- **WHEN** 对指向可交互元素的有效引用执行点击
- **THEN** 该元素被实际点击（触发其点击行为）且返回成功结果

#### Scenario: 输入文本
- **WHEN** 对文本输入类元素执行输入操作并给出文本
- **THEN** 该元素的当前值更新为所给文本且返回成功结果

#### Scenario: 下拉选择
- **WHEN** 对下拉选择控件执行选择操作并给出选项
- **THEN** 该控件选中指定选项且返回成功结果

#### Scenario: 勾选与取消勾选
- **WHEN** 对勾选类控件分别执行勾选与取消勾选
- **THEN** 控件状态相应变为选中与未选中，且每次均返回成功结果

#### Scenario: 滚动
- **WHEN** 对页面执行指定方向的滚动
- **THEN** 页面按该方向发生滚动且返回成功结果

#### Scenario: 条件等待成功
- **WHEN** 执行等待操作且给出条件与超时时间，条件在超时前满足
- **THEN** 返回成功结果

#### Scenario: 条件等待超时
- **WHEN** 执行等待操作且给出条件与超时时间，条件在超时前未满足
- **THEN** 返回失败结果并携带超时错误信息

#### Scenario: 元素操作失败
- **WHEN** 对不存在、隐藏或不可交互的元素执行操作
- **THEN** 返回失败结果并携带可分类的错误信息，且不改变页面状态

### Requirement: 文件函数

系统 SHALL 提供下载与上传能力：download 触发下载并保存文件，upload 向文件选择控件写入文件；失败时返回携带错误信息的失败结果。

#### Scenario: 触发下载并保存
- **WHEN** 对指向下载链接/按钮的引用执行下载并给出保存目录
- **THEN** 下载文件被保存到指定目录且返回成功结果

#### Scenario: 上传文件到控件
- **WHEN** 对文件选择控件执行上传并给出本地文件路径
- **THEN** 该控件接收到指定文件且返回成功结果

### Requirement: HTTP 监听

系统 SHALL 自动监听页面上下文中发生的请求，提供清理记录能力与按 method + URL 模式匹配的响应读取能力；读取操作只对清理后新发生的请求生效。

#### Scenario: 记录并读取页面请求
- **WHEN** 清理记录后页面发生一次匹配某 method 与 URL 模式的请求，随后按该 method 与模式读取
- **THEN** 返回该请求的响应内容

#### Scenario: 清理后旧记录不可读
- **WHEN** 记录若干请求后执行清理，随后按原方法与原模式读取
- **THEN** 不再返回任何此前记录的响应

#### Scenario: 无匹配记录
- **WHEN** 按一个从未发生过的 method 与 URL 模式读取
- **THEN** 返回无匹配结果，而非错误

### Requirement: 独立 HTTP 请求

系统 SHALL 提供不经页面的独立 HTTP 请求能力，请求的认证信息由调用方显式提供，系统不从页面会话自动附加 cookie 或 token。

#### Scenario: 发起独立请求
- **WHEN** 调用方给出 method、URL、headers 与 body 发起独立请求
- **THEN** 返回对应响应，且页面无任何加载或跳转行为

#### Scenario: 认证信息显式传递
- **WHEN** 调用方在 headers 中传入带认证信息的请求
- **THEN** 请求携带调用方给出的认证头，且不自动附加任何页面会话 cookie

### Requirement: 页面截图

系统 SHALL 提供对指定页面的截图能力，将当前页面状态保存为 PNG 文件并返回可用的文件路径。

#### Scenario: 保存页面截图
- **WHEN** 对指定页面执行截图并给出保存路径
- **THEN** 生成 PNG 文件，返回该文件的路径，且文件可被读取

### Requirement: DOM 爬取

系统 SHALL 提供按指定页面与 LOD 参数的 DOM 爬取能力，返回含节点树、role、可见性、包围盒与程序化值的快照；爬取只覆盖主文档，不合并 iframe 内元素，不处理懒加载、虚拟滚动与动态渲染，并剔除隐藏、零尺寸与 aria-hidden 元素。

#### Scenario: 返回结构化快照
- **WHEN** 对页面执行 DOM 爬取并给出 LOD 参数
- **THEN** 返回含节点树、role、可见性、包围盒 bounds 与程序化值的结构化快照

#### Scenario: 程序化值反映最新状态
- **WHEN** 页面中输入元素的值被修改后再次爬取同一页面
- **THEN** 快照中该元素的值反映最新状态

#### Scenario: 隐藏元素被剔除
- **WHEN** 页面中存在 display:none 或 aria-hidden 的元素
- **THEN** 快照不包含这些元素

#### Scenario: iframe 内容不合并
- **WHEN** 页面包含 iframe
- **THEN** 快照只包含主文档的元素，不包含 iframe 内元素

### Requirement: 操作结果与错误语义

系统 SHALL 让每次操作返回携带成功状态、失败原因与附加信息的结果；确定性程序侧失败（元素不存在、网络超时等）返回可分类的失败结果，致命错误（浏览器崩溃、网络断开）抛出终止整个流程的致命异常。

#### Scenario: 成功结果携带成功状态
- **WHEN** 一次操作执行成功
- **THEN** 返回成功状态且失败原因为空

#### Scenario: 程序侧失败可分类返回
- **WHEN** 出现元素不存在或网络超时等程序侧错误
- **THEN** 返回失败结果并携带可分类的错误码与错误信息

#### Scenario: 致命错误终止流程
- **WHEN** 发生浏览器崩溃或网络断开等致命错误
- **THEN** 抛出致命异常并中断整个执行流程
