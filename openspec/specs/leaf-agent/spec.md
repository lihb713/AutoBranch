# leaf-agent Specification

## Purpose

实现 Action / Condition 叶子节点的 agent 式执行：将节点自然语言描述与当前语义图交给 LLM，由 LLM 自主决定调用引擎函数或判断条件真伪，引擎只提供兜底终止条件与错误日志，是行为树"LLM 有界执行"能力的执行核心。

## Requirements

### Requirement: Action 叶子节点的 agent 式执行

系统 SHALL 以 agent 式执行 Action 叶子节点：将节点的自然语言动作描述与当前页面语义图作为输入提供给 LLM，由 LLM 自主决定调用哪些引擎函数（如点击、输入、选择）以及作用于哪个元素，直至返回结果或触发终止条件。

#### Scenario: LLM 结合描述与语义图完成操作
- **WHEN** 引擎执行一个 Action 叶子节点，节点描述为"在用户名输入框输入 admin"
- **THEN** 系统向 LLM 提供该节点描述与当前语义图，LLM 自主调用 type 函数完成输入
- **THEN** 系统返回该 Action 的执行结果为成功或失败，作为叶子节点状态

#### Scenario: 描述无法对应语义图元素
- **WHEN** 语义图中找不到与节点描述匹配的目标元素，LLM 多次尝试后仍无法定位
- **THEN** 系统将该 Action 记为失败并标记为 LLM 侧失败
- **THEN** 系统沿行为树传播该失败，并在执行追踪中记录终止原因
### Requirement: Condition 叶子节点的 agent 式判断

系统 SHALL 以与 Action 相同的 agent 式方式执行 Condition 叶子节点：将节点的自然语言断言描述与当前语义图作为输入提供给 LLM，由 LLM 自主判断条件是否满足，推理期间引擎不介入，最终返回确定的布尔值作为该 Condition 节点的状态依据。

#### Scenario: 条件满足返回真
- **WHEN** 引擎执行一个 Condition 叶子节点，节点描述为"页面上出现'订单号：12345'"，且语义图表明该文本存在
- **THEN** 系统返回确定的布尔值真，作为该 Condition 节点的成功状态

#### Scenario: 条件不满足返回假
- **WHEN** 引擎执行一个 Condition 叶子节点，节点描述为"登录按钮是灰的"，且语义图表明按钮未禁用
- **THEN** 系统返回确定的布尔值假，作为该 Condition 节点的失败状态

#### Scenario: LLM 无法得出确定判断
- **WHEN** 语义图信息不足以让 LLM 得出确定的真或假，且已触发定位终止条件
- **THEN** 系统将该 Condition 记为失败并标记为 LLM 侧失败
### Requirement: 多轮定位

系统 SHALL 允许 LLM 在单次叶子执行中多次调用语义图接口（每次可指定不同的范围与详细程度 LOD）以逐步缩小或放大搜索视角，直到锁定目标元素或判定失败；搜索控制权（看哪里、看多细、是否回溯到更大范围）完全归 LLM。

#### Scenario: 逐步缩小范围定位目标
- **WHEN** LLM 首次获取整页语义图后无法直接锁定目标元素
- **THEN** 系统允许 LLM 以更小的范围或更高的 LOD 再次调用语义图接口，直到定位成功或判定失败

#### Scenario: 回溯放大重新选择区域
- **WHEN** LLM 在某个区域中定位失败
- **THEN** 系统允许 LLM 返回更大范围重新获取语义图并选择其他区域继续定位

#### Scenario: 语义图反映最新页面状态
- **WHEN** LLM 多次调用语义图接口
- **THEN** 系统每次都返回完整生成、反映当前页面最新状态的语义图，不返回缓存的旧数据
### Requirement: 引擎兜底终止条件

系统 SHALL 为每个叶子执行设置兜底终止条件：任一触发即终止该叶子、记为 LLM 侧失败并沿行为树传播。终止条件包括 LLM 对话轮数上限、LLM 连续多轮无进展（结果未变或重复相同调用）、以及单叶子执行超时；引擎只设置与检测终止条件，不干预 LLM 的处理过程。

#### Scenario: 达到对话轮数上限
- **WHEN** 叶子执行中的 LLM 工具调用轮数达到上限
- **THEN** 系统终止该叶子，记为 LLM 侧失败，并在执行追踪中记录触发条件为轮数上限

#### Scenario: 连续无进展
- **WHEN** LLM 连续多轮结果未变或重复相同调用，被引擎判定为无进展
- **THEN** 系统终止该叶子，记为 LLM 侧失败，并在执行追踪中记录触发条件为连续无进展

#### Scenario: 单叶子执行超时
- **WHEN** 单个叶子的执行时长超过设定的超时阈值（纳入全局超时）
- **THEN** 系统终止该叶子，记为 LLM 侧失败，并在执行追踪中记录触发条件为超时
### Requirement: 函数失败回传与 LLM 自主修正

系统 SHALL 将引擎函数调用失败（如点击失败）作为工具调用结果回传给 LLM，由 LLM 自行查看错误并修正（换函数、重新定位、换元素或放弃）；引擎不判断该不该重试，只统计轮数并记录错误日志。

#### Scenario: 函数失败后 LLM 修正并继续
- **WHEN** LLM 调用点击函数失败，引擎以工具结果返回错误信息
- **THEN** 系统将该错误作为工具结果回传给 LLM
- **THEN** 若 LLM 随后以修正后的调用成功完成操作，系统按成功记录该叶子

#### Scenario: 函数失败后 LLM 决定放弃
- **WHEN** LLM 多次修正后仍无法成功执行
- **THEN** 系统允许 LLM 结束该叶子，并按 LLM 返回的失败结果记录
### Requirement: 程序侧致命错误终止流程

系统 SHALL 将无法恢复的程序侧致命错误（如浏览器崩溃、网络断开）直接终止整个流程，而非作为工具结果回传 LLM；此类错误属于程序侧失败。

#### Scenario: 浏览器崩溃
- **WHEN** 叶子执行过程中发生浏览器崩溃等致命错误
- **THEN** 系统终止整个执行流程，并将该叶子标记为程序侧失败
- **THEN** 系统在执行追踪中记录程序侧失败的分类信息
### Requirement: 错误分类与分流

系统 SHALL 按错误源对叶子失败进行分类：LLM 侧失败（定位失败、语义理解失败、判断失败）与程序侧失败（浏览器崩溃、网络超时、元素不存在等确定性执行错误），两类失败的处理语义不同且必须在结果中明确区分。

#### Scenario: 定位失败归为 LLM 侧
- **WHEN** 叶子失败原因是 LLM 无法从语义图中定位目标或理解节点语义
- **THEN** 系统将该失败分类为 LLM 侧失败，供报告向用户提示完善文档或补充 CSS

#### Scenario: 网络超时归为程序侧
- **WHEN** 叶子失败原因是网络超时等确定性程序执行错误
- **THEN** 系统将该失败分类为程序侧失败，供外层判断为可重试的失败
### Requirement: 叶子执行接口契约

系统 SHALL 对外提供统一的叶子执行入口，输入为叶子节点与执行上下文，输出包含执行状态（成功/失败）、Condition 专有的布尔值、失败时的错误来源分类，以及完整的执行追踪数据；该契约同时供编排器触发执行与报告机制回溯。

#### Scenario: Action 执行返回状态
- **WHEN** 编排器以 Action 叶子节点调用叶子执行入口
- **THEN** 系统返回包含执行状态（成功或失败）的结果，失败时附带错误来源分类

#### Scenario: Condition 执行返回布尔值
- **WHEN** 编排器以 Condition 叶子节点调用叶子执行入口
- **THEN** 系统返回包含确定布尔值的结果，作为该节点的状态依据

#### Scenario: 结果包含完整追踪数据
- **WHEN** 叶子执行结束
- **THEN** 系统返回的追踪数据包含 LLM 输入（节点描述与语义图）、LLM 推理过程、实际工具调用序列以及触发的终止条件，供报告机制回溯
### Requirement: 叶子执行的提示词设计

系统 SHALL 为叶子执行提供统一的系统提示词，将节点自然语言描述与当前语义图转化为可靠的决策依据，指导 LLM 正确调用引擎函数、执行多轮定位与得出判断；提示词随输入保持稳定，使相同输入下的 LLM 决策可被回归验证。

#### Scenario: 固定输入下决策可回归
- **WHEN** 以固定的节点描述与固定语义图作为 LLM 输入
- **THEN** 系统以一致的方式组织输入并提供给 LLM，使决策结果可被记录并与后续运行比较以回归保护

#### Scenario: 提示词引导函数调用
- **WHEN** LLM 收到 Action 叶子节点的描述与语义图
- **THEN** 系统提供的提示词使 LLM 得以选择并调用合适的引擎函数与目标元素，而非直接给出无法执行的结果
### Requirement: 两级能力选择执行

Action / Condition 叶子节点的 agent 式执行 SHALL 支持两级能力选择：① 向 LLM 提供能力概览与框架工具 `use_capability`；② LLM 选能力后引擎加载该插件（`init`）并将其函数追加进工具集，供 LLM 细选调用。叶子执行 SHALL 支持一次执行内多轮、多能力（能力可中途追加）。系统 SHALL NOT 在叶子执行前强制预取语义图；改为在提示词中强调"操作/判断前先调用 `semantic_graph` 获取最新语义图"，由 LLM 自主决定。

#### Scenario: 叶子加载能力并调用其函数
- **WHEN** Action 执行时 LLM 调用 `use_capability("browser")` 后调用 `open`
- **THEN** 浏览器插件被加载、`open` 被调用，结果回填给 LLM

#### Scenario: 一个叶子使用多能力
- **WHEN** 某叶子先加载浏览器打开页面、再加载计算能力运算
- **THEN** 两次能力加载与调用在同一叶子执行内完成

#### Scenario: 无强制语义图预取
- **WHEN** 执行一个纯计算叶子（不涉及浏览器）
- **THEN** 不预取语义图，零浏览器开销
### Requirement: 变量写入落笔

叶子执行器 SHALL 负责变量写入落笔：当 LLM 调用**产出型工具**（声明了单一变量目标参数）时，执行器 SHALL 拆出目标参数、调用插件函数、把返回值写入当前帧的目标变量；插件函数 SHALL NOT 直接写变量空间。目标变量 SHALL 在节点的 `NewParam.` 声明集内（= Action / Condition 描述文本中 `NewParam.x[:类型]` 标注的变量集合）；多返回值映射仅经 FunctionCall 节点 `returns` 完成。

#### Scenario: 产出型工具返回值写入变量
- **WHEN** LLM 调用产出型工具（如 `extract(ref, target=结果)`）
- **THEN** 执行器拆出 `target`、调用插件函数、把返回值写入 `结果` 变量

#### Scenario: 目标未声明被拒绝
- **WHEN** 产出型工具的目标变量不在节点 `[[set]]` 声明集内
- **THEN** 执行器拒绝写入并返回错误结果给 LLM
### Requirement: 报告信息随返回值产出

叶子执行 SHALL 把插件函数返回值中携带的报告附加信息（结构化）写入报告（经统一 reporting 接口），插件 SHALL NOT 直接调用报告器。

#### Scenario: 插件附加报告信息
- **WHEN** 插件函数返回值含报告附加信息
- **THEN** 叶子执行器将其写入报告，渲染时按来源展示
